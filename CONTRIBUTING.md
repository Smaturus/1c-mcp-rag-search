# Как контрибьютить

Спасибо, что заглянули. Проект учебный, но правила как в рабочем репозитории:
небольшие атомарные изменения, зелёный CI, данные решений — в документации.

## Настройка окружения

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -e ".[dev]"
```

Полная индексация требует локальной выгрузки 1С — см. README. Для разработки
самого кода индекса не нужен: unit-тесты работают без ML-стека.

## Перед PR

```powershell
ruff check .        # линтер
mypy                # типы
pytest -q           # unit-тесты (33)
```

Все три проверки должны проходить; CI повторит их на Python 3.11 и 3.12.

## Правила изменения retrieval-кода

Если меняете поиск, токенизацию, RRF, reranker или gold-set:

1. Пересоберите нужные индексы (`python scripts/build_bm25.py` при необходимости).
2. Прогоните eval: `python scripts/eval_pipeline.py` (для метрик с разбросом —
   `python scripts/eval_stability.py`).
3. Приложите в PR таблицу «было/стало» по nDCG@10 и MRR@10 и укажите латентность.
4. Решения, меняющие дефолтное поведение, фиксируйте новым ADR в `docs/adr/`.

Мы сознательно не «крутим» пайплайн под результат: если конфигурация проигрывает,
она остаётся в таблице с честным выводом.

## Стиль

- Python 3.11+, type hints, docstrings на русском.
- Форматирование — `ruff format` (line length 100).
- Коммиты в стиле Conventional Commits: `feat:`, `fix:`, `docs:`, `ci:`, `chore:`.
- Не добавляйте в репозиторий выгрузки 1С, индексы, личные данные и секреты.

## Данные и приватность

`data/chroma/`, `data/bm25/`, `vacancies/`, `cover_letters/` и личные заметки
исключены через `.gitignore`. Если добавляете новый артефакт — убедитесь, что он
не содержит путей пользователя и текстов выгрузки.
