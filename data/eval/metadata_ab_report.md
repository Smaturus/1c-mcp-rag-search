# A/B: источник метаданных — текстовый отчёт vs XML-выгрузка

Дата: 2026-10-22
Скрипты: `scripts/parse_config_xml.py`, `scripts/build_metadata_index.py`,
`scripts/eval_metadata_xml.py`

## Методика

- 300 кейсов, сгенерированных из самой выгрузки (структурная истина):
  «реквизиты <тип> <имя>», «измерения и ресурсы регистра <имя>»,
  «значения перечисления <имя>», «у <тип> <имя> где хранится реквизит <поле>».
- Проверка: нужное имя (и поле, если спрашивали поле) попало в top-3.
- Для обеих коллекций применяется **одинаковый текстовый матч** — сравнение
  честное, без преимущества одной стороны за счёт разметки.
- BM25 — собственный индекс (`bm25.py`), одинаковая токенизация.

## Результат

| Источник метаданных | Чанков | BM25 Hit@3 |
|---|---|---|
| текстовый отчёт (`.txt`) | 23 808 | 93,0 % (279/300) |
| XML-выгрузка | 25 026 | **99,7 % (299/300)** |

Прирост: **+6,7 п.п.**

## Качество XML-коллекции по типам (top-3)

| Тип кейса | Кейсов | vector | BM25 |
|---|---|---|---|
| attribute | 133 | 87,2 % | 100 % |
| enum | 40 | 100 % | 100 % |
| object | 85 | 45,9 % | 96,5 % |
| register | 42 | 69,0 % | 95,2 % |
| **Итого** | **300** | **74,7 %** | **98,3 %** |

## Почему XML лучше

1. **Нет обрезки 512 токенов.** У старой коллекции 78 % чанков были длиннее
   лимита e5, поэтому хвост текста не влиял на вектор. Новые чанки — «объект»
   или «поле» — укладываются в лимит по построению.
2. **Структура.** Реквизиты, ТЧ, измерения/ресурсы, формы, команды и значения
   перечислений стали отдельными записями, а не сплошным текстом отчёта.
3. **Чистота.** Шумовые виды (картинки, стили, роли, интерфейсы) исключены:
   26 450 → 25 026 чанков.
4. **Полнота полей.** В отчёте часть структуры отсутствовала или шла прозой.

## Оговорки

- Первая версия оценки давала 17,7 % — это была ошибка методики (запрос
  «где хранится реквизит Организация» без имени объекта), а не деградация.
  После исправления: vector 74,7 %, BM25 98,3 %.
- Векторный baseline старой коллекции восстановить нельзя: Chroma не сохранила
  векторы в sqlite (баг персистентности HNSW). Для строгого сравнения семантики
  нужен переэмбеддинг старых чанков — отдельный замер.
