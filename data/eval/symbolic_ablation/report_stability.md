# Символическая нарезка на текущем экспорте: устойчивость (4 прогона)

Недостающая клетка 2×2 «текущий экспорт × символьная нарезка (1200/200)».
Корпус: `data/chroma`, коллекция `code` (100 445 чанков); gold-set v2 — 70 запросов,
file-level релевантность, дедупликация источников, k=10.

Метрики — **mean ± std** по 4 независимым прогонам в отдельных процессах.
HNSW не персистится (chroma#7090), поэтому top-k слегка меняется между запусками —
разброс ниже и есть шум прогонов. Режим `hybrid_rerank` не запускался (медленно, для клетки не нужен).

## Что важно для 2×2

1. **На текущем экспорте с символьной нарезкой hybrid лидирует над vector**:
   0.2051 против 0.1647, то есть на +0.040. Это же направление во всех 4 прогонах
   (разрывы +0.040 / +0.026 / +0.054 / +0.042), поэтому «лидер» здесь не случаен.
2. Парный тест по 4-прогонным средним (ndcg@10, n=70): Δ = vector − hybrid = −0.0404,
   bootstrap 95% CI [−0.0966; +0.0090], paired t-test p = 0.142, bootstrap p = 0.121,
   побед/ничьих/поражений: 13 / 43 / 14. Направление в пользу hybrid, но на 70 запросах
   статистически **не значимо** — это и не требуется для клетки абляции.
3. Против исторической клетки «старый экспорт × символьная» (vector 0.1764 / hybrid 0.2091,
   3 прогона, `data/eval/v2/report_stability.json`): текущие значения ниже на
   −0.0117 / −0.0040. Это **в пределах шума прогонов** (σ = 0.0131 / 0.0066 у текущей
   клетки и 0.0053 / 0.0030 у исторической), «эффект экспорта» для символьной нарезки
   практически нулевой и не меняет порядок режимов.

## Как измерялось (важно для воспроизводимости)

- Исходный `data/chroma` открывался только на чтение: побайтовая копия
  `chroma.sqlite3` в `.tmp/chroma_symbolic_copy`, оригинал не изменялся.
  Причина: Chroma 1.5.9 требует записи при открытии базы (в read-only окружении падает
  с `attempt to write a readonly database`), а sandbox сессии запрещает запись в индекс.
- Сырые прогоны: `.tmp/symbolic_ablation/report_pipeline.json` (run 1),
  `.tmp/symbolic_ablation_run2..run4/report_pipeline.json` (runs 2–4).
  В репозиторий они не переносились из-за размера (~300 КБ/прогон); сводка — в
  `report_stability.json`.
- Команда прогона:
  `python scripts/eval_pipeline.py --golden data/eval/gold_set_v2.jsonl --chroma-dir <copy> --collection code --modes vector,pearson,hybrid --out-dir <run_dir>`
