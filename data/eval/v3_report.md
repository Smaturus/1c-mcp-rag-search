# v3 hold-out: результаты после фикса BM25 и решение по ADR 0009

**Дата:** 2026-10-23 · **Набор:** [`gold_set_v3_holdout.jsonl`](gold_set_v3_holdout.jsonl)
(100 независимых запросов, 23 домена) · **Отчёт о составе:**
[`gold_set_v3_report.md`](gold_set_v3_report.md).

Правило: v3 **не использовался для настройки**. Дефолт `MCP_1C_SEARCH_MODE=hybrid`
не менялся; после найденного дефекта токенизатора BM25 он снова подтверждён.

## Главный результат: дефект BM25, а не смена лидера

Старый токенизатор не разбивал CamelCase: запрос «заказ покупателя» не совпадал
с `ЗаказПокупателя`, а процедурная нарезка повторяет такие идентификаторы в
каждом чанке. Из-за этого лексический канал деградировал, и hybrid проигрывал
vector. После фикса (см. ADR 0010) на **v2 dev, 4 прогона**:

| Режим | nDCG@10 |
|---|---|
| `vector` | 0.331 ± 0.028 |
| `pearson` | 0.383 ± 0.040 |
| `lexical` | 0.426 ± 0.000 |
| `hybrid` | **0.442 ± 0.012** |

Paired `vector − hybrid`: Δ = **−0.112**, 95 % CI **[−0.184; −0.038]**,
p = **0.0037** — hybrid значимо лучше. Старые 0.339/0.301 были измерены
с дефектным токенизатором и больше не являются действующими.

## Retrieval, 71 code-запрос, 3 прогона (k=10, mean ± std)

| Режим | Hit@1 | MRR@10 | nDCG@10 | Recall@10 |
|---|---|---|---|---|
| `lexical` (BM25) | 0.141 | 0.228 | 0.218 | 0.293 |
| `vector` | 0.089 ± 0.022 | 0.203 ± 0.027 | 0.208 ± 0.020 | 0.319 ± 0.025 |
| `pearson` | 0.113 ± 0.024 | 0.228 ± 0.029 | **0.229 ± 0.019** | 0.342 ± 0.014 |
| `hybrid` | 0.094 ± 0.016 | 0.215 ± 0.019 | 0.217 ± 0.015 | 0.339 ± 0.021 |

Paired `vector − hybrid`: Δ = **−0.0097**, 95 % CI **[−0.0492; +0.0297]**,
p = **0.635** — различие не значимо; hybrid не хуже vector, а на v2 — значимо
лучше. На v3 `pearson` формально первый (0.229), но разрыв с hybrid в пределах
шума; отдельный paired-тест для pearson не делался и не используется для выбора
дефолта.

Metadata-scope (5 запросов, 3 прогона, индикативно): `lexical` 0.677,
`vector` 0.533 ± 0.115, `pearson` 0.533 ± 0.115, `hybrid` **0.767 ± 0.058**
(после фикса BM25; n=5 — только как сигнал, не для решения).

## Роутер на v3

`58/100 (58 %)`; на отвечаемых — `43/76 (57 %)`. По ожидаемому маршруту:
lexical **12/35 (34 %)**, vector **22/30 (73 %)**, hybrid **24/35 (69 %)**.
Главная ошибка — `lexical → hybrid` (21 случай): правила ждут CamelCase/код,
а естественные имена в кавычках уходят в безопасный hybrid. Это разрыв
контракта, а не ошибка разметки; исправления проверять на dev-наборе, не на v3.

## Решение по ADR 0009

**ADR 0009 отклонён (rejected).** Его посылка «лидер сменился hybrid → vector
из-за процедурной нарезки» не подтвердилась: после фикса BM25 hybrid снова
впереди на v2 (p = 0.0037) и не хуже vector на v3 (p = 0.635). Причина
наблюдавшегося сдвига — дефект токенизатора, усиленный повторяющимися
CamelCase-идентификаторами в процедурных чанках.

| Старое условие accepted | Результат |
|---|---|
| paired p < 0.05 и CI без 0 на v3 | **FAIL**: p = 0.635, CI включает 0 |
| max/chunk-level не схлопывает отрыв | не проверено; отрыв не подтверждён |
| ablation подтверждает вклад нарезки | **недействительно**: старый 2×2 снят дефектным токенизатором |
| per-file BM25 ≥ 0.34 | **FAIL**: lexical nDCG@10 = 0.218 |
| хотя бы одна гипотеза подтверждена/опровергнута | **PASS**: гипотеза о смене лидера опровергнута |

**Дефолт `hybrid` не меняется.** Новое решение и доказательства — ADR 0010.

## Что дальше

1. Не тюнинговать на v3; для следующей итерации — новый hold-out.
2. Перезамерить metadata-scope и 2×2 ablation с исправленным токенизатором.
3. Разобрать разрыв роутера `lexical→hybrid` на dev-наборе.
4. Проверить code-oriented embedding / reranker как следующий кандидат, но
   только на dev и с подтверждением на независимом наборе.

## Гигиена

Платформенное имя продукта в исходных запросах заменено нейтральным
«конфигурация»; смысл и разметка не менялись. Raw per-query JSON-файлы
(`report_pipeline.json`) не коммитятся: в них остаются имена реальных
источников корпуса; агрегаты и paired-отчёты воспроизводимы скриптами.
