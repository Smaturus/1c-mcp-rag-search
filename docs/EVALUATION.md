# Оценка качества

Документ описывает, **как измеряется retrieval** и какие значения считаются
актуальными. Сырые отчёты и их статусы — в [data/eval/README.md](../data/eval/README.md),
история изменений методики — в [HISTORY.md](HISTORY.md).

## Принципы измерения

- **Единица релевантности — файл-источник**, а не чанк (ADR 0003).
- **Повторные чанки схлопываются** до уникальных файлов до расчёта метрик
  (ADR 0004), иначе nDCG завышается.
- **k = 10**; считаются Hit@1, MRR@10, nDCG@10, Recall@10.
- **Несколько независимых прогонов**: каждый — новый процесс, HNSW
  пересобирается при старте, поэтому `mean ± std` показывает устойчивость.
- **Парный тест** по per-query значениям: bootstrap 95 % CI (10 000
  ресемплингов, seed = 42) и paired t-test; Wilcoxon — только справочно.
- **Разделение dev / hold-out**: v2 использовался для разработки, v3 — для
  финальной проверки. На v3 правила и режимы не настраивались.

| Набор | Размер | Назначение |

## Текущие результаты

### v2, 70 запросов, 4 прогона

Корпус `code_proc` (154 560 чанков), production-токенизатор BM25.

| Конфигурация | Hit@1 | MRR@10 | nDCG@10 | Recall@10 |
|---|---|---|---|---|
| `lexical` | 0.271 | 0.355 | 0.426 | 0.571 |
| `vector` | 0.164 ± 0.018 | 0.266 ± 0.026 | 0.331 ± 0.028 | 0.511 ± 0.044 |
| `pearson` | 0.207 ± 0.038 | 0.313 ± 0.039 | 0.383 ± 0.040 | 0.562 ± 0.053 |
| **`hybrid`** | **0.221 ± 0.008** | **0.368 ± 0.010** | **0.442 ± 0.012** | **0.652 ± 0.024** |

`lexical` измерен одним прогоном (детерминированный индекс).

Парный тест `vector` против `hybrid` (n = 70 пар):

| Показатель | Значение |
|---|---|
| Δ nDCG@10 (`vector` − `hybrid`) | −0.112 |
| 95 % bootstrap CI | [−0.184; −0.038] |
| paired t-test, p | 0.0037 |
| Побед / ничьих / поражений | 22 / 22 / 26 |

Вывод: на dev-наборе `hybrid` значимо лучше `vector`.

### v3 hold-out, 71 code-запрос, 3 прогона

| Конфигурация | Hit@1 | MRR@10 | nDCG@10 | Recall@10 |
|---|---|---|---|---|
| `lexical` | 0.141 | 0.228 | 0.218 | 0.293 |
| `vector` | 0.089 ± 0.022 | 0.203 ± 0.027 | 0.208 ± 0.020 | 0.319 ± 0.025 |
| `pearson` | 0.113 ± 0.024 | 0.228 ± 0.029 | 0.229 ± 0.019 | 0.342 ± 0.014 |
| `hybrid` | 0.094 ± 0.016 | 0.215 ± 0.019 | 0.217 ± 0.015 | 0.339 ± 0.021 |

Δ(`vector` − `hybrid`) = −0.0097, CI [−0.0492; +0.0297], p = 0.635 —
разница не значима, `hybrid` не хуже. Именно поэтому дефолт остаётся
`hybrid`: он выигрывает на v2 и не проигрывает на независимом наборе.

### v3 metadata, 5 запросов, 3 прогона

Индикативно из-за малого n: `hybrid` 0.767 ± 0.058, `lexical` 0.677,
`vector` 0.533 ± 0.115 (nDCG@10).

## Маршрутизация

| Проверка | Результат | Как читать |
|---|---|---|
| Регрессия, 68 кейсов | 68/68 (100 %) | проверка контракта; кейсы участвовали в настройке |
| Blind Part-3, 20 кейсов, до правок | 15/20 (75 %) | единственная независимая проверка; гейт 80 % не пройден |
| Blind Part-3 после правок | 20/20 | набор стал dev, оценкой обобщения не является |
| v3, 100 запросов | 58/100 (58 %) | 43/76 на отвечаемых; основная ошибка — `lexical→hybrid`, 21 случай |

Вывод: маршрутизация **не ухудшает** качество относительно fixed `hybrid`, но
доказанного прироста нет. Правила — ADR 0006; долг — новый независимый
hold-out для маршрутов.

## Латентность

CPU, без GPU, текущий корпус (v2 / v3): `lexical` ~8–17 мс, `vector` ~50–105 мс,
`hybrid` ~100–120 мс, `pearson` ~85–160 мс, `hybrid_rerank` ~2,4 с/запрос. Подробные замеры — в
[`data/eval/code_proc/report_stability.md`](../data/eval/code_proc/report_stability.md).

## Как воспроизвести

Опубликованные сводки уже в репозитории: `data/eval/code_proc/report_stability.md`,
`data/eval/code_proc/report_paired.md`, `data/eval/v3_code/report_stability.md`,
`data/eval/v3_code/report_paired.md`. Сырых прогонов `run_*.json` в git нет
(`eval_stability.py` читает только такие файлы в каталоге `--out-dir`).
`eval_paired.py` без аргументов ищет `data/eval/code_proc/run_hybrid_*.json`
и требует `--a` и `--b`.

Чтобы снять числа заново, нужен локальный индекс. Каждый прогон — отдельный
процесс; `report_pipeline.json` копируется в `run_N.json` рядом с остальными:

```powershell
New-Item -ItemType Directory -Force data\eval\_runs\v2, data\eval\_runs\v3 | Out-Null
# v2 dev: четыре отдельных прогона, файлы data\eval\_runs\v2\run_1.json … run_4.json
python scripts\eval_pipeline.py --golden data\eval\gold_set_v2.jsonl --out-dir data\eval\_runs\v2_work
Copy-Item data\eval\_runs\v2_work\report_pipeline.json data\eval\_runs\v2\run_1.json
python scripts\eval_stability.py --out-dir data\eval\_runs\v2
python scripts\eval_paired.py --runs-glob "data/eval/_runs/v2/run_*.json" --a vector --b hybrid

# v3 hold-out: три прогона в отдельном каталоге, чтобы не смешать их с v2
python scripts\eval_pipeline.py --golden data\eval\gold_set_v3_holdout.jsonl --out-dir data\eval\_runs\v3_work --scope code
Copy-Item data\eval\_runs\v3_work\report_pipeline.json data\eval\_runs\v3\run_1.json
python scripts\eval_stability.py --out-dir data\eval\_runs\v3
python scripts\eval_paired.py --runs-glob "data/eval/_runs/v3/run_*.json" --a vector --b hybrid
python scripts\eval_anchors.py

# маршрутизация и метаданные
python scripts\eval_router.py
python scripts\eval_router_v3.py
python scripts\eval_metadata_xml.py
```

## Как читать числа

- Абсолютные значения скромные: e5-small не обучена на BSL-коде, gold-set
  частично синтетический. Корректно сравнивать конфигурации **на одном
  наборе и корпусе**, а не переносить число между версиями.
- `± std` — разброс между прогонами, а не доверительный интервал.
- Разница меньше разброса и незначимая по парному тесту не считается
  улучшением.
- Числа до ADR 0010 сняты дефектным токенизатором BM25 и не сопоставимы с
  текущими; они помечены как `superseded` в индексе отчётов.
