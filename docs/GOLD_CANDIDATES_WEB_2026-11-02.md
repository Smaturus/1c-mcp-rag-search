# Заготовки вопросов из открытых источников (2026-11-02)

Снимок ответа внешнего поиска. Это не результат замера и не состав метаданных выгрузки `УправлениеПроизводственнымПредприятием` (синоним «Управление производственным предприятием, редакция 1.1», версия 1.1.8.2, поставщик AL). Публичные описания УПП 1.3 и справка платформы использованы только как источник формулировок.

В `data/eval/gold_set_v2.jsonl`, `gold_set_v3_holdout.jsonl` и `gold_set_v4_holdout.jsonl` эти строки не добавляются. Индекс, Chroma и BM25 из этого файла не пополняются.

## Сценарий использования

Назначение материала — черновик будущего набора вопросов после решения по текущему кандидату индекса. Пока идёт пилот и полная сборка по `docs/PLAN_E5_BASE_FULL_CONFIG.md`, файл только хранится.

Когда `decision.md` этого плана записан и текущий замер закрыт, отдельная задача разбирает таблицу ниже. Порядок такой:

1. Выбросить строки без конкретной страницы: общий портал, корень форума, описание курса вместо статьи синтаксиса, платная витрина ИТС без открытого текста. Повторы одного URL склеить в один вопрос.
2. Для оставшейся формулировки найти файл в `1C-Corpus\1C_Corpus`. Релевантность — файл выгрузки, не страница в интернете (как в ADR 0003). Имя объекта из таблицы — гипотеза. Нет файла — строка не попадает в набор по коду и XML. Её можно оставить только как вопрос «вне корпуса», и только если такой класс вопросов нужен отдельным решением.
3. Человек подтверждает `relevant_sources`: относительный путь со слэшем `/`, без префикса `1C_Corpus/`.
4. Запись идёт в новый jsonl. v2, v3 и v4 не дополняются: их SHA уже зафиксированы для текущего замера. Числа в `docs/EVALUATION.md` этим файлом не обновляются.
5. Новый набор получает свой SHA и свои пороги. С опубликованными nDCG старых наборов его не сравнивают, пока методика сравнения не описана отдельно.

До этого момента список ниже не является очередью на индексацию и не является gold-set.

## Как довести строку до качества v2

Качество v2 — короткая фраза плюс файл выгрузки, который на неё отвечает. Веб-поиск даёт только фразу. Эту проверку делают локально, после `decision.md`, отдельной задачей. Пока идёт пилот, раздел только хранится.

У v2 два вида вопросов. Точные («ПередЗаписью», «ИнвентаризацияТоваровНаСкладе») берутся из имён в `1C-Corpus\1C_Corpus`, не из форума. Семантические («как начислить НДС с авансов полученных») заканчиваются списком `relevant_sources`: относительный путь к `.bsl` или `.xml` со слэшем `/`, без префикса `1C_Corpus/`. Строка без такого пути ниже v2.

Порядок по одной строке из раздела «Четвёртый поиск»:

1. Открыть URL и убедиться, что дословная цитата есть на странице. Нет цитаты — строка вычёркивается.
2. Искать в `1C-Corpus\1C_Corpus` действие из вопроса, а не имя документа с форума: списание недостачи, сторно выпуска, книга покупок, счёт 76.АВ, распределение прямых затрат, инвентаризация, проведение поступления.
3. Оставлять файл, в котором это действие выполняется. Соседний документ с похожим названием не подходит.
4. Сверить фразу и найденные файлы с v2, v3 и v4. Совпали и смысл, и файл — строка не новый вопрос. «Как закрыть аванс полученный на счете 76АВ» проверять против вопросов v2 про НДС с авансов в первую очередь.
5. Человек подтверждает путь. Подтверждённые строки пишутся в новый jsonl. `gold_set_v2.jsonl`, `gold_set_v3_holdout.jsonl` и `gold_set_v4_holdout.jsonl` не дополняются. Числа в `docs/EVALUATION.md` этим файлом не обновляются.

Из десяти строк четвёртого поиска экзаменом становятся только те, у которых после шагов 1–4 остался свой файл. Остальные остаются в этом файле как черновик. Вторая и четвёртая порции того поиска в работу не берутся.
