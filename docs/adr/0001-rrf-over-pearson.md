# ADR 0001: RRF-гибрид вместо взвешенной метрики Пирсона

- **Статус:** принято
- **Дата:** 2026-10-21
- **Контекст:** MVP использовал `w_cos·cosine + w_bm25·BM25 + w_p·Pearson`
  с min-max нормализацией. Pearson — cosine после центрирования e5, то есть
  почти тот же сигнал; веса подбирались вручную.

## Решение

Основной пайплайн — гибрид cosine + глобальный BM25 через
**Reciprocal Rank Fusion**: `score(d) = Σ 1/(k_rrf + rank_i(d))`, `k_rrf = 60`.
Сырые скоры не смешиваются — только ранги. Pearson остаётся отдельным режимом
`pearson` для сравнения в eval.

## Обоснование

1. RRF не требует калибровки весов и нормализации несравнимых шкал.
2. На gold-set (30 запросов, file-level метрики, mean ± std по 3 независимым
   прогонам) гибрид выигрывает у чистого cosine и у взвешенного гибрида с Pearson:

   | Конфигурация | nDCG@10 | MRR@10 |
   |---|---|---|
   | `vector` | 0.223 ± 0.012 | 0.123 ± 0.018 |
   | `pearson` | 0.272 ± 0.022 | 0.170 ± 0.018 |
   | **`hybrid` (RRF)** | **0.378 ± 0.003** | **0.193 ± 0.003** |

3. Латентность гибрида ~60–100 мс против ~90–155 мс у `pearson` (пересчёт
   эмбеддингов кандидатов).

## Последствия

- Дефолт `MCP_1C_SEARCH_MODE=hybrid`.
- Нужен офлайн-шаг `scripts/build_bm25.py` (51 МБ артефакт, в git не попадает).
- Компоненты `hybrid.py`/`metrics.py` сохранены: они нужны режиму-базелайну и
  `evaluate_retrieval` (Pearson как диагностический сигнал).
