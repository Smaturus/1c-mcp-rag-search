# ADR 0003: Релевантность в eval — на уровне файла-источника

- **Статус:** принято
- **Дата:** 2026-10-21
- **Контекст:** первая версия gold-set задавала эталон как «первые 10 чанков,
  где встречается паттерн». Прогон дал почти нулевые метрики у всех
  конфигураций, включая baseline.

## Решение

Единица релевантности — **файл-источник** (`source`), а не отдельный чанк.
Gold-set хранит `relevant_sources`; eval сопоставляет id результатов с файлами
и считает Hit@1, MRR@10, nDCG@10, Recall@10.

## Обоснование

1. На файл приходится десятки–сотни чанков. Если эталон — произвольные 10 из
   них, ретривер наказывается за возврат других правильных чанков того же файла.
2. File-level метрика устойчива к чанкингу и воспроизводима: смена
   `chunk_size` не ломает сопоставимость прогонов.
3. Recall@k нормируется на `min(|relevant|, k)`, поэтому значения сопоставимы
   между запросами с разным числом эталонов.

## Последствия

- `src/mcp_1c_rag/eval_metrics.py` — чистые функции, покрыты unit-тестами.
- `scripts/make_goldset.py` генерирует 30 запросов: 10 курируемых (файлы заданы
  вручную) + 20 автоматических по реальным модулям; три типа — exact / semantic / trap.
- Ограничение: абсолютные значения скромные из-за синтетической авто-части;
  сравнение конфигураций на одном наборе остаётся корректным.
- **Важно:** файловая релевантность требует схлопывания повторных чанков
  одного файла перед расчётом метрик — иначе nDCG завышается. Реализовано
  в `unique_sources` (см. ADR 0004).
