# ADR 0004: Схлопывание повторных чанков в eval-метриках

- **Статус:** принято (исправление методической ошибки)
- **Дата:** 2026-10-21
- **Контекст:** внешнее ревью кода выявило, что в `eval_metrics.ndcg_at_k`
  каждый возвращённый чанк считался отдельным попаданием. Так как единица
  релевантности — файл-источник, а один файл возвращается несколькими чанками,
  метрика завышалась. В сохранённом отчёте `hybrid_rerank` повторные файлы
  встречались в **22 из 30** запросов; при одном релевантном файле, выданном
  десятью чанками, nDCG мог превысить 1.0.

## Решение

Перед расчётом метрик ранжирование сворачивается до уникальных файлов
(`unique_sources`), порядок определяется первым вхождением файла. Затем
Hit@1, MRR@10, nDCG@10 и Recall@10 считаются по свернутому списку.

## Обоснование

1. nDCG по определению ограничен единицей; дубликаты нарушали это свойство.
2. Файловая релевантность — единица оценки (ADR 0003); считать нужно
   уникальные единицы, а не чанки.
3. MRR и Hit@1 не меняются (первый релевантный файл остаётся первым),
   Recall уже учитывал уникальные файлы — приведены к одной семантике.

## Последствия и новые цифры

Пересчёт на том же gold-set и тех же прогонах (mean ± std по 3 прогонам):

| Конфигурация | nDCG@10 было (с дублями) | nDCG@10 стало (уникальные файлы) |
|---|---|---|
| `vector` | 0.223 | **0.143 ± 0.023** |
| `pearson` | 0.272 | **0.165 ± 0.017** |
| `hybrid` | 0.378 | **0.199 ± 0.015** |
| `hybrid_rerank` | 0.134 | **0.078** |

- Преимущество hybrid над vector по nDCG@10: **+39 %** (было +69 %).
  Часть прежнего отрыва была артефактом учета дублей — тем важнее была ревизия.
- Вывод о выборе hybrid как дефолта **не изменился**: он по-прежнему лучший
  по nDCG/MRR/Recall при минимальной латентности.
- Вывод об отрицательном результате reranker **усилился**: 0.199 → 0.078.
- Добавлены регрессионные тесты: дубликаты не раздувают nDCG, второй
  релевантный файл после схлопывания занимает честную позицию.

## Урок для проекта

Метрика проверяется до публикации: свойство «nDCG ≤ 1» и ручная проверка
нескольких запросов ловят такие ошибки раньше внешнего ревью. В `tests/`
теперь есть тест на это свойство.
