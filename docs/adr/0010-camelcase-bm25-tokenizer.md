# ADR 0010: CamelCase-aware токенизация BM25

- **Статус:** accepted
- **Дата:** 2026-10-23
- **Контекст:** BM25-токенизатор оставлял CamelCase-идентификаторы одним
  токеном. Запрос «заказ покупателя» не совпадал с `ЗаказПокупателя`, а пути
  и заголовки процедурных чанков (`// file: Documents/ЗаказПокупателя/...`)
  повторяют такие идентификаторы. В результате лексический канал деградировал,
  а ADR 0009 ошибочно объяснил смену лидера нарезкой.
- **Решение:** `tokenize` дополнительно разбивает CamelCase и snake_case на
  части, сохраняя исходный токен целиком. Пересобран глобальный BM25
  (`data/bm25_all`: 179 586 документов, 236 320 термов, 81 МБ).
- **Результаты:** v2 dev, 4 прогона, nDCG@10: lexical 0.426, vector 0.331 ± 0.028,
  pearson 0.383 ± 0.040, hybrid **0.442 ± 0.012**. Paired vector−hybrid
  Δ = −0.112, 95 % CI [−0.184; −0.038], p = 0.0037. v3 hold-out, 3 прогона:
  lexical 0.218, vector 0.208 ± 0.020, pearson 0.229 ± 0.019, hybrid
  0.217 ± 0.015; vector−hybrid Δ = −0.010, CI [−0.049; +0.030], p = 0.635.
- **Последствия:** ADR 0009 отклонён; дефолт `MCP_1C_SEARCH_MODE=hybrid`
  сохраняется и теперь подтверждён на dev. Индекс BM25 вырос с ~57 до 81 МБ;
  время сборки ~55 с. Старый 2×2 ablation и metadata-замеры требуется
  переснять исправленным индексом.
- **Проверка:** `python -m pytest tests/test_bm25.py` (токенизация/матчинг),
  `python scripts/eval_anchors.py` (10/10), отчёты
  `data/eval/code_proc/report_stability.md`, `data/eval/v3_code/report_stability.md`.
