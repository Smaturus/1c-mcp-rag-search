# Архитектурные решения (ADR)

Каждое заметное решение фиксируется отдельным ADR: контекст, варианты,
выбор и измеренное обоснование. ADR не переписываются задним числом — при
пересмотре меняется только статус и добавляется ссылка на новое решение.

## Статусы

- **принято** — решение действует в текущем пайплайне.
- **rejected** — решение проверено и отклонено; документ сохранён как
  отрицательный результат и не должен использоваться как текущее описание.
- **superseded** — решение заменено более поздним ADR (в таблице
  указывается, каким именно).

ADR 0009 отклонён после появления ADR 0010: «сдвиг лидера» объяснялся
дефектом BM25-токенизатора, а не свойством процедурной нарезки. Хронология —
в [docs/HISTORY.md](../HISTORY.md).

## Как добавить ADR

1. Скопировать структуру соседнего файла: заголовок, статус, дата, контекст,
   решение, обоснование, последствия.
2. Добавить строку в таблицу выше.
3. Сослаться на ADR из README или ARCHITECTURE, если решение меняет
   наблюдаемое поведение.
