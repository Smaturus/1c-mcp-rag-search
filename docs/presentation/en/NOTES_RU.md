## Отличия от русской колоды (сверять при вопросах)

- **Тесты:** 74 unit tests (было 39 в ранней версии; +2 на CamelCase-токенизатор).
  ruff — 0 замечаний, mypy — 22 модуля, complexity gate — 143 блока, средняя 4.37
  (A), MI min 23.0; CI зелёный (после очистки истории).
- **Фикс BM25 (ADR 0010):** токенизатор теперь режет CamelCase и snake_case,
  сохраняя исходный токен. Причина: «заказ покупателя» не совпадал с
  `ЗаказПокупателя`; процедурные чанки повторяют такие имена, поэтому lexical
  деградировал. Индекс пересобран: 179 586 документов, 236 320 термов, 81 МБ.
- **v2, 4 прогона (nDCG@10):** lexical 0.426, vector 0.331 ± 0.028,
  pearson 0.383 ± 0.040, hybrid **0.442 ± 0.012**. Paired vector−hybrid:
  Δ = −0.112, CI [−0.184; −0.038], p = 0.0037 → hybrid значимо лучше.
- **v3 hold-out, 3 прогона:** lexical 0.218, vector 0.208 ± 0.020,
  pearson 0.229 ± 0.019, hybrid 0.217 ± 0.015; Δ = −0.0097,
  CI [−0.049; +0.030], p = 0.635 — не значимо, hybrid не хуже.
- **ADR 0009:** отклонён; «сдвиг лидера» был артефактом токенизатора, а не
  свойством нарезки. Дефолт `MCP_1C_SEARCH_MODE=hybrid` подтверждён.
- **Старый 2×2 ablation:** числа 0.339/0.301 сняты дефектным токенизатором;
  для объяснения смены лидера не используются, нужен перезамер.
- **Metadata v3 (5 запросов):** hybrid 0.767 ± 0.058, lexical 0.677,
  vector 0.533 ± 0.115 — индикативно.
- **Роутер:** 68/68 на dev; blind Part-3 75 % до патчей, 20/20 после (dev).
  На независимом v3 — 58/100; основная ошибка `lexical→hybrid` (21 случай).
- **Скриншоты:** это РЕАЛЬНЫЙ вывод живого сервера (текущий корпус), снятый
  скриптом с `code_proc` + `metadata_xml`; сырой лог —
  `screenshots/live_capture.txt`. Абсолютные пути в `index_stats` скрыты,
  длинные фрагменты кода сокращены и помечены «…».
  Нюанс: живая база `data/chroma_xml` в песочнице доступна только на чтение,
  Chroma при открытии пишет в sqlite, поэтому капчур делался на копии базы
  (`.tmp/chroma_live`, те же данные); содержимое индекса не менялось.
